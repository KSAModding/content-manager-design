# Decisions

Newest first, one row per accepted RFC. This table answers "what did we decide". The RFC itself answers "why".

| Date | RFC | Decision |
|---|---|---|
| 2026-09-14 | [0058](rfcs/0058-listing-images-and-dates.md) | An authored document gets an optional `[images]` table with one square icon and the images its description references as `ksa-image:<id>`, each a record with a URL on the author's host plus `sha256`, `width`, `height` and `size` that the checks and every client verify, and a client shows no other image in a description; the snapshot gets the derived optional fields `published_at` and `updated_at`, and `spec_version` and `snapshot_version` stay at `1`. |
| 2026-09-13 | [0052](rfcs/0052-static-download-counts.md) | The generated index repository carries a static `download-counts.json` with the download counts GitHub and SpaceDock report per listing and version, and the snapshot attaches them as an optional `downloads` field; an absent count means unknown, and counts never affect resolution, installation, ownership or moderation. |
| 2026-09-13 | [0049](rfcs/0049-instance-handover.md) | A `mod-loader` listing states how it is told which instance to run in a `[provides.instance]` table, a command line flag that takes the instance root as the next argument, an environment variable that carries it, or both, and a manager fills in only the absolute instance root; nothing else in RFC 0035 changes and `spec_version` stays at `1`. |
| 2026-08-15 | [0048](rfcs/0048-ownership-of-an-edit.md) | Ownership of an edit is evaluated against the authority the listing's base version names, and not against the authority the submitted document names; pointing a listing at a different release host verifies against both, a repository GitHub redirects to a new address is a rename rather than a move, and whether a listing already exists is read from the base branch and never from the file status a host reports. |
| 2026-08-10 | [0038](rfcs/0038-repository-topic-ownership-proof.md) | The ownership check accepts a third proof: the repository topic `ksa-index-<login>`, set by an administrator of the release host and naming the claiming account's login, evaluated between RFC 0033's owner-id fast path and the marker file; it closes the organization-owned repository case and changes nothing else in RFC 0033. |
| 2026-08-09 | [0035](rfcs/0035-content-install-descriptor.md) | Every content type gets an `[install]` descriptor on its authored file, an anchor plus relative path with per-type defaults and prose-only steps, and a mod loader adds `[provides]` naming its launch target, content directory, and the closed configure contract a manager machine-writes; RFC 0031's install table becomes this superset without a spec_version bump. |
| 2026-08-09 | [0033](rfcs/0033-content-index.md) | The community index lives in two GitHub repositories, authored plus generated, with a scheduled watcher stamping releases and self-service listing gated by automated ownership verification; clients fetch one snapshot artifact from a stable address with normal HTTP caching, moderation speaks through index-side states, and humans act only on disputes, takedowns, delisting, and listings whose ownership cannot be verified automatically. |
| 2026-08-08 | [0031](rfcs/0031-content-metadata-format.md) | One metadata format for every content type, a shared authored core plus per-type extensions; a mod or mod loader is one authored TOML file plus one tooling-stamped JSON file per release, a pack is one authored document per version with exact pins, ids share one global case-insensitive namespace, and a published release accepts only narrowing amendments. The vehicle and save types themselves stay a future RFC. |
| 2026-08-04 | [0025](rfcs/0025-scope.md) | The project is a content manager covering mods, mod packs, vehicles, and saves, with the content type a required metadata field from day one; the index is our own on free infrastructure, StarMap stays an external dependency, Borea is the implementation, and the repository is renamed to match. |
| 2026-08-03 | [0017](rfcs/0017-game-version-ordering-and-compatibility.md) | KSA releases are ordered by their revision alone; a mod's compatibility is a revision range with a required lower bound and an optional open upper bound. |
